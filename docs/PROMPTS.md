# 요청 문장 가이드 — 기획자 · 디자이너용

AI 도구(Claude Code · Cursor)에 이렇게 말하면 HDS로 조립된 화면이 나옵니다. 규칙(`AGENTS.md`)은 도구가 알아서 읽습니다. 여러분은 **무엇을, 어떤 데이터로, 어떤 상태까지**만 말하면 됩니다.

## 기본 틀

> **[화면 이름]을 만들어. [src/mock의 어떤 데이터]를 쓰고, [핵심 요소 2~3개]. [상태].**

예:

> 패키지 상품 목록 화면을 만들어. src/mock의 packages를 쓰고, 상단에 필터 칩(지역 · 가격대), 각 상품은 썸네일 · 제목 · 가격 · 라벨, 하단 고정은 없음. 로딩과 검색 결과 없음 상태도.

## 자주 쓰는 패턴

| 하고 싶은 것 | 이렇게 말한다 |
| --- | --- |
| 새 화면 | 「○○ 화면을 만들어. src/mock의 △△ 데이터를 써」 |
| 단계 추가 | 「package-payment 화면에 결제수단 앞에 '탑승자 연락처 확인' 단계를 넣어. TextInput 두 개(이름 · 휴대폰)」 |
| 컴포넌트 바꾸기 | 「여행자 목록의 ListCell density를 compact로」 · 「하단 버튼을 dual-prominent로, 왼쪽은 '장바구니'」 |
| 상태 보강 | 「쿠폰이 하나도 없을 때 EmptyState compact를 보여줘」 · 「결제 실패 Toast negative를 추가해」 |
| 모양 비교 | 「같은 화면을 두 버전으로: A는 결제수단을 RadioItem 목록, B는 SegmentedControl. 둘 다 등록해」 |
| 반응형 | 「tablet(768)에서는 요금 요약을 오른쪽 열에 두고 본문은 왼쪽」 |
| Figma에서 | 「이 Figma 링크 화면을 HDS 컴포넌트로 구현해: https://www.figma.com/design/…?node-id=…」 (Figma MCP가 연결돼 있을 때) |

## 이렇게 말하면 도구가 멈추거나 엉뚱하게 만듭니다

- ✗ 「예쁘게」 「모던하게」 「트렌디하게」 — 기준이 없어 임의 스타일이 나옵니다. HDS에 맡기세요.
- ✗ 「파란 버튼」 「글자 좀 더 크게 16px」 — 토큰 규칙에 걸려 lint가 실패합니다. 「Button tone을 secondary로」 「title/md로」처럼 **HDS 이름**으로 말하세요. 이름은 `AGENTS.md` 4절 인덱스에 있습니다.
- ✗ 「실제 API 붙여서」 — 범위 밖입니다. 목데이터만 씁니다. 데이터 모양이 더 필요하면 「src/mock/booking.ts에 ○○ 필드를 더해」라고 하세요.
- ✗ 「전체 홈 화면」 — 컴포넌트가 없는 영역이 많아 커스텀이 쏟아집니다. 플로우의 **한 단계**로 좁히세요.

## HDS에 없는 게 필요할 때

그냥 요청하세요. 도구는 `data-hds="custom" data-hds-reason="…"`을 붙여 만들고, `npm run check`가 그 목록을 냅니다. 리뷰 때 「이 커스텀은 HDS에 넣을 것인가」를 같이 정합니다. **커스텀이 나오는 게 실패가 아니라, 커스텀이 안 보이는 게 실패입니다.**

## 끝내기 전

```bash
npm run check
```

통과하면 푸시 → 미리보기 주소 공유 → 30분 리뷰 → 폐기 / Figma 정본화 / 이관 중 하나.
